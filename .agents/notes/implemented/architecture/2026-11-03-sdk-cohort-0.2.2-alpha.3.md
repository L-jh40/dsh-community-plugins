# Agent Note: SDK cohort 0.2.2-alpha.3

Status: implemented

## Problem

The community-plugin index and its inert compatibility row tracked 0.2.1-rc.3 while the supported host moved to 0.2.2-alpha.3. The cohort and Node floor need to move without changing the community catalog or claiming that the inert row is a plugin-management feature.

## Decision

SDK development dependencies move to `^0.2.2-alpha.3` and Cordis to `^4.0.6-alpha.2`; the host engine and peer floors are `>=0.2.2-alpha.3`. CI runs Node 24.9.0. The lockfile, release-age ledger, README badges and pairing hashes move together. The inert Cordis row and the community catalog keep their existing semantics, and the eleven-module browser platform table is unchanged.

## Alternatives considered

**Use the official plugin index as a replacement for the Workshop catalog.** Rejected: the official index discovers plugin packages only, while this repository also supplies the Workshop's community metadata and remains the source for the market build.

**Change community entries during the cohort move.** Rejected: catalog content and SDK compatibility are independent concerns, so no entries are added, removed or reclassified.

**Publish a new package as part of the cohort move.** Rejected: no release was requested and the package version stays unchanged.

## Consequences

Frozen installation passes the supply-chain policy check. Typecheck, both Vitest tests, the build and `pnpm community:check` (151 entries) pass. The inert row keeps existing profiles resolving, and no package is published to npm; dsh-web consumes the updated working-tree content through its normal satellite workflow.
