# Agent Note: SDK cohort 0.2.1-rc.3

Status: implemented

## Problem

The community plugin index tracked 0.2.1-rc.2 while the supported host moved to 0.2.1-rc.3. Although this package is primarily an index data source with an inert cordis row, its declared host floor, SDK development graph, and shared build contracts still need to move together.

## Decision

The eleven consumed SDK development dependencies move to `^0.2.1-rc.3`. `dsh.engines.dsh` and the `@deepseek-ai/dsh` peer both declare `>=0.2.1-rc.3`; the bilingual README badges and pairing hashes follow. Cordis stays `^4.0.5` because the cohort keeps that version.

The lockfile is rebuilt from a clean resolution. The release-age ledger keeps its append-only union rows as `0.2.1-rc.2 || 0.2.1-rc.3`, adds the new `dsh-client-ui-entry-customization` package, and covers every one of the 299 resolved rc.3 packages in an automated audit.

The package still ships no client bundle and needs no SDK source adaptation. The shared browser platform table remains the same eleven rows, so only its verification provenance changes. `community.json` and the catalog's behavior are untouched.

## Alternatives considered

**Drop the rc.2 members while advancing the ledger.** Rejected: the established union is append-only history, not a list that should be rewritten to hide earlier resolutions.

**Treat the inert row as a reason to skip the cohort update.** Rejected: existing profiles still resolve the row, and its engine and peer declarations remain user-visible compatibility contracts.

**Publish the index package with a new version.** Rejected: this is the repository's compatibility change, not an explicit release request.

## Consequences

`pnpm install --frozen-lockfile --ignore-scripts` passes the supply-chain policy check. `pnpm typecheck`, `pnpm test` (2 tests), `pnpm community:check` (143 entries), `node --test scripts/community-index.test.mjs` (9 tests), and `pnpm build` pass. The rebuilt committed `lib/` is unchanged.

No `@linxin666` version changes and nothing is published to npm. The repository owns its cohort commit; dsh-web moves the submodule pin after that commit is available on this repository's remote `main`.
