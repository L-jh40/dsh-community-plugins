# Agent Note: SDK cohort 0.2.2-rc.1

Status: implemented

## Problem

The community-plugin index and its inert compatibility row tracked 0.2.2-alpha.3 while the supported host moved to the published 0.2.2-rc.1 release cohort (with Cordis 4.1.0 and vendor 1.1.0/1.2.0/1.9.0 packages). The cohort and release-age ledger need to advance without altering the community catalog or the inert row's semantics.

## Decision

SDK development dependencies move to `^0.2.2-rc.1` and Cordis to `^4.1.0`; the host engine and peer floors move to `>=0.2.2-rc.1`. The lockfile, release-age exclusion ledger (pruning retired alpha.3/alpha.2 entries), README badges and bilingual pairing hashes move together. The inert Cordis row, community catalog and eleven-module browser platform table remain unchanged.

## Alternatives considered

**Stay on 0.2.2-alpha.3 declarations under a 0.2.2-rc.1 host.** Rejected: keeping prerelease alpha floors and lockfile entries splits the workspace cohort from the shipped release candidate.

**Modify catalog entries during the cohort update.** Rejected: catalog curation is independent of SDK cohort alignment.

**Publish a new npm version as part of the cohort move.** Rejected: no release was requested, so the package version stays unchanged.

## Consequences

`pnpm install --frozen-lockfile --ignore-scripts` passes supply-chain policy verification. `pnpm community:check` (151 entries), the 9 index script tests, `pnpm typecheck`, the 2 Vitest tests and `pnpm build` all pass. No package is published to npm; dsh-web links the updated working tree locally through its satellite profile workflow.
