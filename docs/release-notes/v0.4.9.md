社区插件索引随 dsh-web 家族对齐到统一版本 0.4.9。本版本收录一条社区插件条目，索引条目总数从 142 增至 143；同一区间的提交还把 SDK 开发依赖图与声明的宿主下限整体推进到 0.2.1-rc.3。

> **兼容性**：本版本没有破坏性变更。包名 `@linxin666/dsh-client-ui-community-plugins` 与安装方式不变，`community.json` 仍是工坊商店插件列表与 dsh-market.com 插件清单的唯一数据源，其文件名、条目结构与字段名不变；bundle patch 里那行惰性 `ui-community-plugins` 行不变；线协议字段与 profile 里已持久化的键名均未改名或改形。唯一与兼容性相关的变化是宿主下限收紧：`dsh.engines.dsh` 与 `@deepseek-ai/dsh` peer 从 `>=0.2.1-rc.2` 抬到 `>=0.2.1-rc.3`，仍停留在 rc.2 的宿主需要先把 dsh 升到 rc.3 才能安装本版本，本索引自身的安装与读取路径不受影响。

### 新功能

- 收录日志查询 `dsh-loglens`（#45）：Elasticsearch / OpenSearch 上的日志查询卡片，一个查询面里给按来源方言的查询串与可点例子、字段名补全、筛选芯片、可点柱缩放时间窗的时间分布、把分组的桶点成筛选的字段面板，以及带级别染色与堆栈续行标记的结果列表（可选列、可翻页）；Docker 容器日志作为采集来源复用 docker 插件。agent 侧五个只读 `loglens_*` 工具（sources / search / fields / facets / context）与面板共用同一执行层。出站只打到已配置的来源、按解析后的 IP 判定、不跟随重定向，并有体积与超时上限。作者 hyzyn，`tools/dev` 类目，与其余 hyzyn 条目相邻

### 修复

- 本区间没有可归入「修复」的提交：v0.4.8..HEAD 的三个非合并提交分别是一次条目收录、一次 Agent Note 记录与一次 SDK 队列推进，均未修正既有行为

### 其他改动

- 版本从 0.4.8 对齐到 0.4.9：本包是单包仓库，`package.json` 的 `version` 是唯一的版本声明点；本提交只动这一个字段，不动依赖、不动 `dsh.engines.dsh`、不动 lockfile
- SDK 队列推进到 0.2.1-rc.3：十一项 SDK devDependency 到 `^0.2.1-rc.3`，`dsh.engines.dsh` 与 `@deepseek-ai/dsh` peer 到 `>=0.2.1-rc.3`，双语 README 徽章与 README.i18n.yaml 的配对哈希跟进；cordis 保持 `^4.0.5`。lockfile 从干净解析重建，release-age 账本保持 append-only 并并上 rc.3 行、新增 `dsh-client-ui-entry-customization` 包，299 个 rc.3 包全部纳入自动审计；`shared/web-platform.ts` 只改验证来源注释，十一行浏览器平台表未变
- Agent Note：记录 2026-10-20 注册轮次——十二个 PR 同时追加 `community.json` 尾部且一轮只落一条，先批七次待批工作流运行把未知变成结论；#45 合入，#41 因其分支上 `community.json` 第 1672 行少一个逗号而坏、按文件而非内容驳回，五条按证据保留，#32 与 #38 仍只差分支更新，#18 按陈旧关闭。另一篇记录本次 0.2.1-rc.3 队列
- 本包不构建客户端 bundle：`src/` 自 v0.4.8 起未改动；`lib/` 不入库，由发布流水线在 `pnpm build` 时生成

The community plugin index publishes on the family's aligned version 0.4.9. This release registers one community plugin entry, growing the index from 142 to 143 entries; the commits in the same range also advance the SDK development dependency graph and the declared host floor to 0.2.1-rc.3.

> **Compatibility**: there are no breaking changes in this release. The package name `@linxin666/dsh-client-ui-community-plugins` and its install path are unchanged, `community.json` remains the single data source for the Workshop store plugin list and the dsh-market.com plugin manifest with the same filename, entry shape and field names, the inert `ui-community-plugins` row of the bundle patch is unchanged, and no wire-protocol field or profile key that is already persisted has been renamed or reshaped. The one compatibility-relevant change tightens the host floor: `dsh.engines.dsh` and the `@deepseek-ai/dsh` peer move from `>=0.2.1-rc.2` to `>=0.2.1-rc.3`, so a host still on rc.2 must upgrade dsh to rc.3 before it can install this version. The index's own install and read paths are unaffected.

### New Features

- Register the log query card `dsh-loglens` (#45): a query surface over Elasticsearch and OpenSearch with per-dialect query strings and clickable examples, field-name completion, filter chips, a time histogram whose bars zoom into that window, a field facet panel that turns a bucket into a filter, and a result list with level colors, stack-continuation rows, selectable columns and paging; Docker container logs are a collection source that reuses the docker plugin. Five read-only `loglens_*` tools on the agent side (sources / search / fields / facets / context) share the same execution layer as the panel. Outbound requests only reach configured sources, judged on the resolved IP, do not follow redirects, and carry size and timeout caps. By hyzyn, filed under `tools/dev` next to the other hyzyn entries

### Fixes

- Nothing in this range belongs under Fixes: the three non-merge commits in v0.4.8..HEAD are one entry registration, one Agent Note record and one SDK cohort advance, and none of them corrects existing behaviour

### Other Changes

- The version moves from 0.4.8 to 0.4.9: this is a single-package repository, so `version` in `package.json` is the only place the version is declared, and this commit touches that one field only. No dependency, no `dsh.engines.dsh` value and no lockfile entry moves with it
- The SDK cohort advances to 0.2.1-rc.3: the eleven consumed SDK devDependencies move to `^0.2.1-rc.3`, `dsh.engines.dsh` and the `@deepseek-ai/dsh` peer declare `>=0.2.1-rc.3`, and the bilingual README badges and their README.i18n.yaml pairing hashes follow; cordis stays `^4.0.5`. The lockfile is rebuilt from a clean resolution, the release-age ledger keeps its append-only union rows, gains the rc.3 rows and the new `dsh-client-ui-entry-customization` package, and covers all 299 resolved rc.3 packages in an automated audit. `shared/web-platform.ts` changes only its verification provenance comment; the eleven-row browser platform table is unchanged
- Agent Notes: record the 2026-10-20 registration round, where twelve pull requests appended to the same `community.json` tail and only one could land per round, and seven pending workflow runs were approved first so that an unknown became a verdict; #45 merged, #41 was held on a broken file rather than on content (its branch drops the comma after `dsh-delete-archived`'s `descriptionEn` and the array stops parsing at line 1672), five hold on evidence, #32 and #38 still need only the branch update, and #18 closed as stale. A second note records this 0.2.1-rc.3 cohort
- This package builds no client bundle: `src/` is unchanged since v0.4.8; `lib/` is not committed and is produced by `pnpm build` in the release pipeline
