### 新功能

- 无：本区间没有新增功能，也没有新增或修改索引条目（`community.json` 仍为 143 条）

### 修复

- 无：本区间没有修正既有行为的提交

- 仅版本对齐，内容与 0.4.10 一致：本包是单包仓库，`package.json` 的 `version` 是唯一的版本声明点（`git grep` 全仓确认无第二处声明）；本提交只动这一个字段并新增这份 release notes，不动依赖、不动 `dsh.engines.dsh`、不动 lockfile

- 索引数据未因发版变更：`pnpm community:check` 在本次发版前通过（143 条），本提交不触碰 `community.json`

The community plugin index publishes on the family's aligned version 0.4.11. This release changes nothing in this repository: the range `v0.4.10..v0.4.11` holds no commits other than this version-alignment commit, so the index data, the sources and the behaviour are identical to 0.4.10. The version moves for family alignment only.

> **Compatibility**: there are no breaking changes in this release. Every frozen identifier is unchanged: the package name `@linxin666/dsh-client-ui-community-plugins`; the install path (the same package name from the registry, with the same `files` list and the same `exports` entry points); the persistence identifiers (`community.json`'s filename, entry shape and field names, plus the already-persisted `ui-community-plugins` mount row and the related profile keys); and the wire protocol (the inert `ui-community-plugins` row of the bundle patch and the fields the plugin exposes to the host) are neither renamed nor reshaped. The host floor stays at `>=0.2.1-rc.3` in `dsh.engines.dsh` and the `@deepseek-ai/dsh` peer: it is neither tightened nor relaxed, so any host on rc.3 or later installs this release directly.

### New Features

- None: nothing was added in this range, and no index entry was added or modified (`community.json` still holds 143 entries)

### Fixes

- None: no commit in this range corrects existing behaviour

### Other Changes

- Version alignment only; the content is identical to 0.4.10: this is a single-package repository, so `version` in `package.json` is the only place the version is declared (a repository-wide `git grep` confirms there is no second declaration point), and this commit touches that one field and adds this release note. No dependency, no `dsh.engines.dsh` value and no lockfile entry moves with it
- Equivalent to the previous release: the only difference between this release and 0.4.10 is the version string in `package.json`. `community.json`, `cordis.patch.yml` and `icon.svg` are untouched, and `src/` is unchanged since v0.4.9 and never references the package version, so the `lib/` it builds is the same as 0.4.10's. `lib/` is not committed (it is in `.gitignore`) and is produced by `pnpm build` in the release pipeline
- The index data does not change with this release: `pnpm community:check` passes before it (143 entries), and this commit does not touch `community.json`
